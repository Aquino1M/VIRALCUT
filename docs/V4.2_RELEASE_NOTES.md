# ViralClip Studio V4.2 — Adaptive Smart Studio

## Objetivo

V4.2 amplia o V4.1 sem trocar sua base estável. O pipeline continua local-first e ganha uma camada de orquestração capaz de escolher CPU local, GPU local ou **Lightning CPU grátis** por tarefa.

## Garantia de custo Lightning

Esta distribuição foi construída em modo **FREE CPU ONLY**:

- `LIGHTNING_FREE_CPU_ONLY=True` não pode ser desligado por `.env`;
- `cloud_gpu` é rejeitado pelo scheduler;
- o cliente recusa um worker que anuncie GPU/máquina paga;
- o worker remoto também recusa execução se detectar GPU;
- não há código para iniciar T4/GPU ou trocar hardware via Lightning SDK;
- render remoto é bloqueado;
- Lightning indisponível sempre cai para processamento local.

O usuário deve criar/usar apenas o primeiro Studio gratuito de 4 CPUs e configurar URL/token manualmente conforme `LIGHTNING_FREE_CPU_SETUP.md`.

## Adaptive Compute Fabric

Novas tabelas: `processing_tasks`, `performance_samples`, `scheduler_decisions`, `task_cache`, `clip_revisions`, `creator_performance`.

Nós suportados:

- `local_cpu`;
- `local_gpu` quando detectada;
- `cloud_cpu` (Lightning free CPU).

O scheduler estima conclusão usando benchmark/histórico real, fila, cold-start informado, transferência e carga atual local. Toda decisão é persistida para diagnóstico e aprendizagem posterior.

## Worker Lightning v3

O pacote `lightning_worker/` contém o worker remoto CPU-only:

- FastAPI + SQLite WAL;
- 1 heavy slot;
- uploads chunked/resumíveis com SHA-256;
- deduplicação por hash;
- FFprobe após montagem do upload;
- idempotency key por job;
- cache de resultados;
- heartbeat e lease;
- recuperação de jobs interrompidos após restart;
- cancelamento e SSE `/jobs/{id}/events`;
- retenção/cleanup de mídia temporária;
- ASR com `faster-whisper-cpu`, highlights sem LLM remoto, tracking em proxy e embeddings locais.

## Inteligência editorial

- ViralScore 3.0 preserva o V2 como fallback e adiciona estrutura (pace/open loop/payoff), modalidades somente quando medidas e calibração opcional por histórico real.
- Creator Intelligence aprende duração e sinais por plataforma somente com dados observados cadastrados.
- Busca semântica e Q&A local retornam trechos do transcript como evidência e não inventam fatos.

## Editor e Auto Edit

- Prompt-to-Edit determinístico/não destrutivo;
- checkpoint antes de cada comando;
- histórico e restore de revisões;
- progress bar e Ken Burns no Auto Edit;
- loudness normalizado opcional (`-14 LUFS`, `TP -1.5`) quando habilitado;
- Quality Guard 2.0 para timeline, safe zones, FFprobe e presets de plataforma;
- Thumbnail Brain seleciona o melhor frame entre amostras por nitidez, exposição e face.

## Biblioteca de projeto

- painel de Compute por projeto;
- busca semântica no transcript;
- Templates e Brand Kits com JSON versionado de import/export;
- Brand Kit com overrides de CTA por YouTube Shorts, TikTok e Instagram Reels.

## Compatibilidade

O Worker Protocol v1 local continua anunciado como `heavy_processing=local-worker`; V4.2 expõe separadamente `compute_orchestrator=adaptive-compute-fabric`. Isso evita quebrar clientes/diagnósticos V3/V4.1.

`pytest.ini` agora inclui `pythonpath=.`; a suíte pode ser executada com `pytest -q` sem configurar `PYTHONPATH` manualmente.
